# Interview Qbank Builder

> 通用、多人复用的求职面试题库与口语化自我介绍构建器（Codex Skill）。

本 Skill 面向不同候选人与岗位，生成事实受控、谦逊口语化、能够直接练习的面试材料。构建前会先确认候选人真实背景、目标岗位 JD、知识库或事实材料链接、公司名称、岗位名称和题库根目录；信息不完整时不会猜测候选人经历。

## 核心能力

- 前置资料门禁：确认候选人背景、目标岗位 JD、知识库或事实材料（没有时明确记录“无”）。
- 按公司归档：默认保存到
  <题库根目录>/<公司名称>/<公司名称>-<岗位名称>-面试题库.md，同一公司不同岗位相互隔离。
- 已有题库风格抽取：生成自我介绍前扫描题库根目录下的 Markdown/TXT，抽象可复用的表达风格，但不复制任何候选人的个人事实。
- 稳健工科口语风：教育背景定锚 → 岗位相关经历 → 具体动作与验证 → 能力总结 → 岗位落点与谦逊意愿。
- 事实受控：区分主导、参与、协助和了解，不把 JD、外部面经或团队成果写成候选人的个人事实。
- 完整交付：一分钟与 30 秒自我介绍、20~30 道面试题、可能追问、避坑提示、反问清单和临场速记卡。
- 小红书可选模块：只有用户明确要求搜索小红书、参考小红书面经或高频题时，才通过 agent-reach 开启；普通生成题库默认不调用 xhs，也不检查登录态。

## 标准工作流

1. 交互式确认候选人背景、目标岗位 JD、知识库链接（或明确无知识库）、公司名称、岗位名称和题库根目录。
2. 检查目标公司目录与已有题库，必要时读取其中的自我介绍和风格说明，提取表达规律。
3. 建立事实边界与 JD 映射，标注已证实、待确认和不可声称内容。
4. 默认跳过小红书。只有用户明确授权后，才执行 xhs status、xhs whoami，认证通过后再用 xhs search 检索公开面经。
5. 基于候选人事实、JD、已确认知识库和（如开启的）外部面经信号生成材料。
6. 写入公司目录，完成路径、内容和事实边界验证。

## 小红书检索规则（可选）

### 默认关闭

用户只说“生成题库”“准备面试”或类似请求时，视为未授权小红书检索：

- 不调用 agent-reach 的 xhs 命令；
- 不检查小红书登录态；
- 不因没有小红书样本而阻塞题库生成；
- 题库中注明“小红书检索：未开启”。

### 用户明确要求时开启

当用户明确要求搜索小红书、参考小红书面经、查找小红书高频题或类似表达时：

1. 先通过 agent-reach 执行 xhs status 和 xhs whoami。
2. 若未认证、登录过期、缺少 a1 Cookie、Session expired、渠道不可用或出现验证码/风控，立即暂停小红书模块和后续题库生成。
3. 提示用户在浏览器或扫码完成登录；不得索取、保存或展示 Cookie、Token 或浏览器存储内容。
4. 用户回复“已登录”后，从 xhs status 和 xhs whoami 重新检查，认证通过后才继续搜索。
5. 使用公司名、岗位名、面试题、面经和行业方向等组合查询；外部内容只决定题目覆盖和追问方向，不改变候选人事实。

具体命令和摘要字段见 references/xhs-search.md。

## 输出路径与文件规则

默认路径：

    <题库根目录>/
    └── 公司名称/
        ├── 公司名称-岗位名称-面试题库.md
        ├── 公司名称-岗位名称-小红书面经摘要.md  # 仅在用户明确开启小红书时按需生成
        └── 公司名称-岗位名称-面试复盘.md        # 面试后按需生成

写入规则：

- 公司名称、岗位名称或题库根目录不明确时先询问，不创建文件；
- 不删除历史题库；
- 未经用户明确要求不覆盖同名文件，可追加版本说明或生成新版本；
- 小红书未开启时不伪造面经摘要，只在题库中注明未开启；
- 写入后必须通过目录列表和文件读回验证最终路径及内容。

详见 references/output-paths.md。

## 自我介绍风格

统一采用“稳健工科口语风”：

1. 教育背景定锚；
2. 选择 1~2 段与 JD 最匹配的真实经历；
3. 说明具体动作、验证方式和结果；
4. 总结 1~2 个岗位相关能力；
5. 落到目标岗位，并表达愿意从具体模块或工程环节做起。

一分钟版本通常约 220~280 个汉字，30 秒版本约 120~160 个汉字。技术名词必须附着在真实动作之后；优先使用“参与过、做过、负责其中的、形成了一定理解、希望从具体模块做起”等克制表达，避免无证据的“精通”“全面负责”“独立完成整套系统”“完全胜任”。

详见 references/introduction-style.md。

## 本地软连接安装

按工作区约定，源码应位于 E:\GitHubWorkspace，运行入口使用 Windows Junction 指向原件目录：

    git clone https://github.com/anklecrusher/interview-qbank-builder.git E:\GitHubWorkspace\own\opensource\interview-qbank-builder
    cmd /c mklink /J "C:\Users\<用户名>\.codex\skills\interview-qbank-builder" "E:\GitHubWorkspace\own\opensource\interview-qbank-builder"

验证：

    Get-Item "C:\Users\<用户名>\.codex\skills\interview-qbank-builder" | Select-Object Name, LinkType, Target

应看到 LinkType 为 Junction，且目标指向 E 盘原件仓库。不要在 .codex\skills 中复制一份实体 Skill 内容。修改 E 盘原件后，运行入口会自动读取更新。
